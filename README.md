# tweets

近況つぶやきを旧Twitter風のUIで公開する静的サイト。

## 更新方法(Macから)

以下の2通りの方法がある。

**A. tweets.txt を直接編集する場合(旧来の方法)**

1. `tweets.txt` の末尾に、空行区切りで新しいつぶやきを追記する。
2. 以下を実行する(HTML再生成 + commit + push を一括で行う)。

   ```bash
   ./post.sh
   ```

   または `つぶやきを投稿.command` をダブルクリックする。

**B. ブラウザのフォームから投稿する場合**

1. `Tweet.app` をダブルクリックする(ターミナルは開かない)。
   Shift を押しながら起動すると、既存のウィンドウにタブを足すのではなく、
   新しいウィンドウで開く。
2. ブラウザが自動で開き、投稿フォームが表示される。
3. テキストエリアに書いて「投稿」を押す(`tweets.txt` への追記 +
   HTML再生成 + commit + push まで自動で行われる)。投稿後もそのまま続けて
   次のツイートを書ける。しばらく操作がないとローカルのサーバーは自動終了する
   (タブはそのまま閉じてよい)。裏側は `compose_server.py` が
   `http://localhost:8765/` で動いている。
4. 「画像を追加」から画像を最大4枚まで添付できる(web版と同じ)。選んだ画像は
   ブラウザ側で必ずJPEGに変換され、長辺1600ピクセルまで縮小される。この過程で
   元ファイルのEXIF(GPS位置情報・撮影日時・機種名など)は引き継がれず、
   残っていないことを確かめてからでないと送信しない。本文には
   `[img:images/...]` の行が付く。
5. 投稿フォームの下には、これまでのつぶやきが新しい順に並ぶ。各つぶやきの
   右上にある編集・引用・削除のボタンから、次の操作ができる(いずれもローカル
   の画面だけの機能で、公開されるサイトにボタンは出ない)。

   - **編集**: その場で本文を書き直せる。件数が変わらないため、`state.json` の
     投稿日時と通し番号はそのまま保たれる。画像と引用は本文とは別に並び、×で
     外したり新しい画像を足したりできる(`[img:...]` や `[rt:...]` の行を手で
     書く必要はなく、本文に書いても拒否される)。本文に空行は置けない。空行は
     つぶやきの区切りなので、1件が2件に分かれて日時との対応が崩れるため。
     編集したつぶやきが他から引用されていた場合、引用カードの中身も自動で
     新しくなる。
   - **削除**: 確認のうえで `tweets.txt` と `state.json` から取り除き、
     再生成 + commit + push まで行う。引用されているつぶやきを消す場合は、
     何件から引用されているかを確認画面で知らせる。
   - **引用**: 押すと投稿欄の上に引用元が表示され、そのまま本文を書いて
     投稿すると引用付きのつぶやきになる(いわゆるリツイート)。本文には
     `[rt:番号]` の行が付き、サイト上では引用元が枠付きのカードで表示される。
     カードをクリックすると引用元の位置まで移動する。

### Tweet.app の中身を直すとき

`Tweet.app` の中身は Swift で書かれていて、ソースは `tweet_launcher.swift`
に置いてある。直したら以下を実行して作り直す(コンパイルと署名まで行う)。

```bash
./build_tweet_app.sh
```

署名が変わるため、作り直した直後の初回起動で「Tweet が Brave Browser を
制御しようとしています」の確認が出ることがある。

アプリがやっているのは、投稿サーバーの起動とブラウザを開くことだけで、投稿や
削除の処理は `compose_server.py` の側にある。以前は AppleScript のアプレット
だったが、Shift の判定に間に合わせるために作り替えた(詳しい経緯は
`tweet_launcher.swift` の冒頭コメントにある)。

## 更新方法(スマホから)

**A. PWA投稿フォームを使う場合(推奨)**

1. スマホのブラウザで https://keisato0.github.io/tweets/post.html を開く
   (あらかじめホーム画面に追加しておくとアプリのように起動できる)。
2. 初回のみ、GitHubのアクセストークンを求められるので入力する。
   github.com の Settings > Developer settings > Personal access tokens >
   Fine-grained tokens で、リポジトリを `keisato0/tweets` のみに限定し、
   Permissions の `Contents: Read and write` だけを許可したトークンを
   発行して貼り付ける(トークンは端末のブラウザにのみ保存される)。
3. テキストエリアに書いて「投稿」を押すと、GitHub API経由で `tweets.txt`
   に直接追記・コミットされる(コミットメッセージは
   `つぶやきを追加(スマホPWA)`)。投稿後もそのまま続けて次のツイートを書ける。
4. 「画像を追加」から画像を4枚まで添付できる。画像はアップロード前に
   ブラウザ内で自動的に処理される。
   - 長辺1600px以下に縮小し、JPEGとして保存し直す(数MBの写真が数百KB程度になる)。
   - GPS位置情報・撮影日時・機種名などのメタデータはすべて削除される。
     削除できなかった場合はアップロードせずにエラーになる。
   - 写真の向き(縦/横)はピクセルに反映されるので、横倒しにはならない。

   画像は `images/` に保存され(コミットメッセージは `画像を追加(スマホPWA)`)、
   つぶやきには `[img:images/ファイル名.jpg]` という1行として書き込まれる。
   `generate.py` はこの行を画像として表示する。タイムラインでは小さなタイルとして
   表示され、クリックすると `lightbox.js` による拡大画面が開く。

**B. GitHubの編集画面を直接使う場合**

1. スマホのブラウザ、またはGitHubアプリで
   https://github.com/keisato0/tweets/edit/main/tweets.txt を開く。
2. 末尾に空行を1行はさんで新しいつぶやきを追記する。
3. そのまま「Commit changes」で `main` ブランチに直接コミットする。

いずれの方法でコミットしても GitHub Actions (`.github/workflows/build.yml`)
が自動で `generate.py` を実行し、生成されたサイトを再度コミット・push
してくれる(数十秒〜1分程度)。Mac側での操作は不要。

新しく追加されたつぶやきには、生成スクリプトを実行した時刻が投稿日時として
割り当てられ、`state.json` に記録される(以後の実行で上書きされない)。
1回の実行で複数のつぶやきを追加した場合は、それらすべてに同じ投稿日時が
付与される。

`state.json` にはあわせて、つぶやきごとの通し番号 `ids` と、次に振る番号
`next_id` を記録する。`timestamps` とまったく同じ位置対応で持っており、
引用(`[rt:番号]`)の参照先として使う。一度振った番号は変わらない。
つぶやきを削除するときは、`tweets.txt` と `state.json` の `timestamps` と
`ids` から必ず同じ位置を取り除くこと。本文だけを消すと末尾が切り詰められ、
それ以降の投稿日時がすべてずれる。

最新100件は `index.html` に、それより古いものは `archive/page1.html`,
`archive/page2.html`, ... に分割される。アーカイブは古いほうから100件単位で
区切るため、`page1.html` が一番古い1-100件目で固定され、一番新しいページ
(件数が100未満になりうる)だけがつぶやきの追加にあわせて増えていく。
`index.html` の「過去のつぶやき」では、新しいページを上、一番古い1-100件目
を一番下に並べる。

各ページの青いトップバーから検索ページ `search.html` に移動できる。
`search.html` は `generate.py` が生成し、検索そのものは同じく `generate.py` が
書き出す `search.json`(全ツイート分)を対象に、`search.js` がブラウザ内で行う。
